# #6 高亮、笔记与草稿恢复

- 沿用 UIKit、Readium 3.11.0 和 library.json 原子提交；Book 的可选 notes/noteDrafts 字段兼容已有书架。标注 UUID 在真实选择时生成，同操作重试复用；提交笔记与移除该 UUID 草稿在一次原子写中完成，写失败不发布成功或破坏已有记录。日常原生阅读位置、设置、书签和其他书籍保持独立。
- 原生选择菜单提供“高亮”“写笔记”和复制。捕获 Readium 当前选择 Locator，再从真实 DOM Selection 补充共同元素 CSS、完整 before/highlight/after 及起止 DOMRange（元素、子节点、UTF-16字符偏移）。同段第二次出现由完整上下文及范围区分，不只按章节、页码或相同 quote 合并。既有同范围再次高亮不提交旧正文、不消费草稿；未提交新笔记草稿也复用身份，高亮仅创建空正文并保留草稿。
- 阅读正文使用 Readium Decoration 显示单一黄色高亮，点击打开对应编辑器；不自行重做 Reader。新增标注销毁全部卷页缓存；每次捕获当前页或邻页快照前，核验 Readium 实际 decoration range、文字、完整前缀和渲染元素已存在。布局／模式变化继续复用 #5 的新导航器和缓存生命周期。
- 笔记栏目按书分组，草稿优先展示，同 UUID 的已提交版本不重复成另一行；个人文字与引用原文分区。列表记录打开编辑器，可明确保存笔记、保存草稿或返回原文。编辑停止0.6秒、离开编辑器和应用失活时尝试补存草稿；状态只在原子写成功后显示已保存，保存失败保留页内输入且阻止带未保存修改直接关闭。强杀只保证最后已提交草稿，不承诺未提交尾字符零丢失。
- 返回原文复用 #4 导航及准确字符可视核验；未核验通过不保存临时导航位置，成功保存真实原生位置。文件不可用明确报错，不猜测重新导入关联。无 AI、检索、导出、备份、云同步、移除书籍或多色系统。

本地原始验证命令、xcresult、截图／落盘及失败边界记录于 .scratch/delivery/issue-6.md；开发测试不代表独立验收或首发完成。真机、iOS16、复杂CSS／RTL／竖排、长书性能和内存压力未验证。
