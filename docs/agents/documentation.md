# 文档

书灯的文档按读者分成两类。两类都写在仓库里，但只有一类对外发布。

## 用户文档（发布）

- 位置：`website/doc/`，由 VitePress 构建为静态站点，经 GitHub Actions 发布到 GitHub Pages。
- 读者：准备安装或正在使用书灯的人。
- 写什么：怎么安装、怎么用、每个功能怎么操作、隐私与费用、常见问题。
- 不写什么：路线图、未发布能力、“暂不支持/后续会支持”、内部 issue、ADR、验收记录、代码类名。
- 术语：与根目录 `GLOSSARY.md` 一致；面向用户的文案用用户语言，例如“选中文字”而不是内部术语“选文”。
- 风格：短句、具体步骤、可核对；不写“总之/首先其次最后/赋能/一站式”这类套话；只描述已发布版本的行为。
- 本地预览：`cd website && npm run docs:dev`；构建：`npm run docs:build`。
- 新增页面：在 `website/doc/` 新建 `.md`，并在 `website/.vitepress/config.mts` 的侧边栏登记。

## 开发文档（不发布）

- 位置：`docs/`，包括 ADR、设计与研究、验收记录和 `docs/agents/` 下的协作约定。
- 读者：维护代码的人。
- 写什么：为什么这样做、架构取舍、验收边界、已知限制、任务追踪规则。可以写路线图和未发布计划。
- 不复制用户文档正文；用户也需要的内容写在用户文档里，这里只放链接。

## 一条信息只有一个出口

同一条信息只写在一个地方。修改产品行为时，同时检查用户文档是否要跟着改；两者冲突时，用户文档描述已发布行为，开发文档描述设计与原因。
