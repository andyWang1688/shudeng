# 项目文档维护规范

目标是让开发者和 Agent 找到完整、可靠、适用于当前任务的依据。按职责组织内容、清除冲突与重复；不设文件数、字数或行数指标，也不把“有链接”当作正文已经足够。

## 文档分工

| 文档 | 负责回答 | 应保留的内容 |
| --- | --- | --- |
| AGENTS.md、docs/README.md | 从哪里开始、何时读什么？ | 高频协作边界、任务导航与必要上下文；主题正文通过条件入口展开。 |
| 根 GLOSSARY.md | 这个词具体指什么？ | 书灯领域定义、相近概念的区别、首选词与避免词；不用它承载步骤、功能清单或实现决定。 |
| docs/product-scope.md | 产品应该怎样工作？ | 功能边界、动作后果、状态、明确例外与可核查场景。 |
| docs/architecture/、docs/design/、docs/agents/ 与模块 README | 该模块或任务怎样正确实现和验证？ | 必要背景、职责/数据所有权、依赖与接口、生命周期、异常处理、操作步骤、验证方法；按主题需要选择，不强套所有章节。 |
| docs/adr/ | 为什么做了这个重要选择？ | 当时背景、决定、真实取舍及取代范围；长期规格链接到当前正文。 |

实际测量与验收进入 docs/validation/YYYY-MM-DD/，已发布版本记录进入 docs/releases/；历史规划、原型、调研和过程记录进入 docs/archive/。用户指南位于 website/doc/，仅描述已发布行为。以上资料各有作用，不能把设计决定、代码现状与验证结果互相替代。

## 从讨论到正文

1. **查事实**：核对已有术语、相关 ADR、规范、源码与必要证据。环境事实由 Agent 查找；若实现与规范不同，说明差异与风险，不直接把代码现状改写为已确认产品决定。
2. **厘清决定**：把未定选择按前置依赖展开，给用户具体场景和推荐方案，解决当前可讨论的分支；已确认规则不重复征询。明确范围、后果及失败情形后再实现新决定。
3. **及时记录**：术语一旦明确就更新 GLOSSARY；行为落在产品规范，工程合同落在对应模块正文；只有符合下述条件的重要决定写 ADR。不把尚未确认的建议写成 accepted。
4. **检查影响**：同步更新受影响的正文、导航与取代关系。一个规则维护一份完整正文，其他位置可概览并链接；概览不能成为另一份独立变更的规则。
5. **验证交付**：核对术语一致、关键边界和例外未丢失、本地链接及资源可用；标注缺失或未验证证据。阶段进度进 Issue/验收，一次性材料用任务临时目录，完成后回收。

## 术语表的格式与边界

保留单一领域布局：根 GLOSSARY.md 与 docs/adr/。当前没有多个独立上下文，不为技术目录另建术语表或 GLOSSARY-MAP。

每个词条用一到两句说明它是什么，必要时列出避免词；按阅读、标注、问答等自然主题分组。定义用产品语言，不包含源码类名、字段结构、工具协议、存储机制、验收命令或“点击后必须”等步骤。

词条示例：

> **书签**：指向书中位置的快捷入口，与记录内容理解的标注区分。
>
> _避免_：书签笔记、书签分类

“书签只在阅读器管理”属于产品规则；“书签如何存储和回跳”属于工程合同；这两者都不塞进定义。设计基准稿、视觉验收、允许适配偏差等开发交付用语放在界面规范中解释。

## ADR 何时写、怎样写

新 ADR 须同时满足：改变决定的成本显著；缺少背景会使后来者疑惑；存在真实备选方案和取舍。常规整理、简单修复、参数微调与容易撤销的布局不因发生过讨论就自动生成 ADR。

ADR 使用 docs/adr/ 的连续编号，先查现有最大编号。最小正文是一到三句：背景是什么、决定什么、为什么；需要时再增加重要备选或非显然的后果，不强套背景/方案/优缺点全套模板。

~~~md
---
status: accepted
date: YYYY-MM-DD
---

# 简短的决定标题

背景、决定与原因。必要时写清取代了哪条旧决定，并链接当前详细规范。
~~~

状态按实际使用 proposed、accepted、deprecated 或 superseded by ADR-NNNN；accepted 仅表示决定获准。后续选择改变时保留原编号和取代关系，不将历史失败改成通过，也不因沿革很长恢复全部讨论到当前 ADR。旧 ADR 不必为了版式统一而重写历史事实。

## 归档与迁移

归档依据是内容的时效和职责。仍有效的约束、失败边界与用户例外先迁入当前正文，再归档旧计划；不能仅因文章长、名称带日期或阶段完成就让持续规则只剩在 archive 中。调研的当前结论可留在主题规范，原始材料按需要追溯。

移动时保持图片、HTML、CSS 与脚本依赖完整，同步修改相对链接、模块入口和仍使用的脚本路径；检查文件未丢失、非文本证据未变、迁移未新增断链。未随工作区保留的历史证据明确标记，不编造恢复结果；永久删除原始资料另按资源和恢复资料规则处理。

## 技能与用户文档

项目技能由[索引](../../.agents/skills/README.md)按任务加载，第三方 SKILL.md 正文保持上游来源，安装记录与 skills-lock.json 一致。项目差异写入本仓库规范，产品运行时 Agent 指令与开发技能分开，不维护全局技能文件。

website/doc/ 经 VitePress 发布；新增页面登记 website/.vitepress/config.mts，命令查 website/package.json。用户文档使用 GLOSSARY 中的领域语言，只说明安装、操作、隐私费用和已发布行为，不混入内部类名、未发布路线图或验收声明。
