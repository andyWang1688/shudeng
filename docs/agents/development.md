# 开发与验证规范

本页用于把已确认的产品行为落实为可评审的代码。产品语义见[产品规范](../product-scope.md)，模块、存储与平台边界见[架构](../architecture.md)，构建和清理必须同时遵守[资源规则](resources.md)。

## 开始与范围确认

1. 查看当前分支、工作区及目标模块，区分用户已有改动和本次工作；不覆盖、回退或顺手提交无关内容。
2. 读取任务涉及的正文、术语与决策，沿源码确认输入如何经过 UI、平台接线、共享业务到保存/输出。事实先查证，真正未定的行为才与用户讨论。
3. 写清本次改变的场景、预期、失败后果与兼容范围；普通修复不借机新增功能或改变接口。需要改变已接受决定时明确说明理由和取代范围。
4. 选择最小但能证明行为的验证范围；涉及平台、设备或真实服务时提前区分自动化能证明和不能证明的部分。

## 实现原则

沿用模块中已存在的接口、错误模型、命名与格式。共享策略、平台适配和页面组合保持职责清晰，抽取稳定的重复职责；不要为统一代码形状合并不同任务的生命周期，或为一次调用增加无用途的抽象层。

常用 UI 交互、聊天能力和 Agent 编排优先采用项目已选成熟组件。引入新依赖先核对实际运行端、版本、许可与构建影响；依赖值从各包 package.json、pnpm-workspace.yaml 及锁文件获取，不在文档维护第二份版本清单。

用户数据、原文映射、取消信号与异步失效保护属于功能合同。失败须定位到实际层次，不能用空结果、占位成功或静默重试遮盖保存、检索和模型错误。兼容代码有消费者或迁移职责时保留，移除前检查调用和数据恢复边界。

## 操作入口

下列命令从仓库根运行，选择本次相关项；各包更多脚本以 package.json 为准。

| 目的 | 入口 |
| --- | --- |
| RN 开发服务 | `pnpm --filter @shudeng/mobile start` |
| 独立视觉 Demo | `pnpm --filter @shudeng/mobile demo:ios`；[运行说明](../../apps/mobile/src/ui/visual-demo/README.md) |
| 类型检查 | `pnpm typecheck`，可按受影响包定向选择。 |
| 现有测试 | `pnpm test`，或 `pnpm --filter @shudeng/core test`、`pnpm --filter @shudeng/mobile test`、`pnpm --filter @shudeng/reader-web test`。 |
| 资源端口与 iOS 构建 | `scripts/test-epub-resources.sh`；`scripts/build-ios-rn.sh Release`，先满足资源规则。 |

reader-web 修改后按[模块说明](../../packages/reader-web/README.md)重新生成，不手改 readerWebHtml/readerFixtures。原生能力通过模块与 Expo 插件维护，不直接修改可再生 Pods/prebuild 输出；依赖补丁由工作区配置声明并保留升级回归方法。

涉及 Python 时依次选择项目虚拟环境、用户级环境、其他可用项目环境，只有没有替代时才使用系统 Python；复用已有环境，不为一次检查重复安装依赖。

## 验证选择与证据

| 改动 | 需要证明的行为 | 证据边界 |
| --- | --- | --- |
| 纯文档或索引 | 规则/术语一致，链接可用，迁移内容和资源完整。 | 无需构建 App。 |
| 共享逻辑或数据 | 关键输入/边界与失败路径；涉及 schema 时含迁移和既有数据。 | Node 单测不代表移动端运行通过。 |
| Agent 或模型协议 | 工具范围、预算/取消、来源、上下文、错误分类与保存重开。 | 受控响应不证明真实模型回答质量或服务商计费。 |
| UI 与交互 | 先用独立 Demo 确认视觉，再复核真实数据、长文本、空/错/中断、键盘与弹层。 | 截图不证明连续手势、辅助技术或生命周期。 |
| 构建/清理或原生接线 | 实际目标运行时；构建脚本改动需连续两轮与失败清理。 | 编译、设备操作、真机性能和发行分别记录。 |

运行与本次改变直接相关的现有检查；行为或失败边界需要保护时补有意义的回归，不为低影响可逆整理写镜像测试。检查通过后若无新改动或未解决疑点，不反复扩大同一轮验证。

验收用具体输入、操作、预期和禁止结果记录实际输出，版本、平台、环境和未验证项清楚。保存到[验收记录](../validation/README.md)时保留最少必要证据，原始密钥和用户书籍内容不写进公开日志。

## 交付与结束

说明改动解决的问题、现在具体能做什么、如何验证及仍存在的限制；示例 Demo、产品接入、测试通过、用户确认与正式发布各自有证据。按[文档维护规范](documentation.md)同步受影响的规则，提交与发布保持本次任务范围，发布另按[流程](release.md)。

一次性脚本、日志、截图与导出集中到任务专属目录，结束时确认归属和进程占用后回收；保留用户交付物、未提交工作和必要恢复资料，不为收尾额外生成无用途报告。
