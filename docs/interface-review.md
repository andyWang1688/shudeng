# 界面评估与优化建议

状态：2026-10-23 的高保真稿和原生返工已完成；用户随后在实际使用中指出信息仍过密，偏好更接近 Apple 的简洁层级。2026-10-25 起以 [ADR-0010](adr/0010-reading-first-progressive-disclosure.md)为新基准，旧稿只作为历史证据，新的设计工作见 [#34](https://github.com/andyWang1688/shudeng/issues/34)。

## 2026-10-23 当前应用反馈

用户试用 v0.1.0 后认为界面缺少设计感，并指出应用图标缺失。当前实现的事实：

- 书架的每本书统一使用 `book.closed` 系统图标，未接入 EPUB 封面（`ios/Shudeng/Sources/App.swift` 的书架单元格）；不能归因于测试书没有封面。
- 项目构建设置指定了 `AppIcon`，但资源中没有对应图标集，应用图标确实尚未接入。原书灯图标的来源与用户授权见 [ADR0001](adr/0001-independent-implementation.md)。
- 用户确认沿用“一盏照书的灯，AI 照亮你读不懂的地方”，并认可暖白底、墨色文字、少量灯光暖色的方向；具体页面通过上述设计稿评审。

下文保留前期参考版本的静态评估，不能将其当作当前应用实测。

## 判断

保留现有四栏、书架网格、按书分组的笔记与对话作为产品基础，重点优化阅读沉浸感、内容层级和导航控件的视觉重量，不进行整套视觉翻新。

## 依据与局限

查看了 ReadAny 仓库中的 `assets/ios/library.png`、`reader.png`、`ai-threads.png`、`notes.png`，以及 `docs/ios-ux-handoff/evidence/195-library-default-after-cleanup.png`。仅观察已有截图，不将图片或界面材料复制到新项目；截图可能早于当前代码，未运行旧应用，不据此确认当前版本仍存在所有问题。

## 建议

| 区域 | 截图所见 | 优化建议 |
| --- | --- | --- |
| 整体 | 简洁中性色、书架网格、分组列表；较大的胶囊控件、阴影及底栏图标 | 保留简洁结构，减少控件和阴影对内容的争抢，统一图标、间距和圆角层级 |
| 阅读 | 顶部书名旁排列多个操作图标，截图中章节标题部分位于工具栏下方 | 工具栏按需显隐，减少首层按钮；显隐时确保正文可读区域正确，不遮挡章节标题 |
| 对话 | 按书分组的历史直观；搜索图标与搜索框同时出现，摘要包含 Markdown 标记 | 保留历史优先，合并重复搜索入口；以问题、引用摘要、时间呈现记录，摘要去除格式语法 |
| 书架 | 搜索、筛选及操作占据上方；书封与下方标题形成清晰网格 | 保留网格，突出继续阅读，弱化次要操作；不因测试样书的灰色封面判定实际书封设计失败 |
| 笔记 | 按书分组，有高亮、笔记、书签筛选，引用和自己的笔记视觉较接近 | 保留分组和筛选，进一步区分引用原文与个人笔记；强化返回原文的可发现性 |
| 设置 | 本轮未查看设置截图；已确认首发支持多套 AI 配置 | 根据新需求明确标识当前配置，连接测试与错误信息应就近展示；此项为需求建议，不是已有视觉问题的认定 |

## 重建时优先验证

- 三种阅读模式切换后位置和标注一致，仿真翻页不妨碍选文和提问。
- 工具栏、键盘及 AI 弹层的显隐不遮挡目标内容，关闭后回到原阅读位置。
- 小屏幕、大字体、深色模式下内容仍可读，操作目标易点击；当前截图不能证明这些条件已满足。
