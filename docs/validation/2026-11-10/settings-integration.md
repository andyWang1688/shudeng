## 设备发现并修复的问题

首轮配置实际保存后，编辑页仍停留且按钮禁用。新增关闭保护沿用了旧导航 API，当前 Expo Router 的 usePreventRemove 需要显式 disablePrevention 或 repeat，重新 dispatch 被拦截动作无法解除保护。现已在明确保存/放弃后关闭保护再退出，系统返回使用 repeat；Small 复测保存返回、继续编辑与放弃修改均通过。新增回归模拟真实阻止删除路由，避免只检查 onClose 被调用。

## AI 服务编辑表单调整

本轮将真实编辑页的展示拆为平台表单，业务与保存生命周期仍由 AIServiceEditor 管理。iOS 使用已有 Expo UI 的 SwiftUI Form、Section、LabeledContent、TextField、SecureField 和 Toggle；保留系统取消/保存工具栏。名称与模型用紧凑行，地址单独换行；已有密钥显示“已保存 · 更换”，取消更换继续使用已保存密钥。未检查时不显示占位状态，检查结果在操作后出现，联网能力与高级设置同组。依据 [Apple Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields) 与 [Entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data)，未将采用系统组件等同于完整 HIG 验收。

“服务商”改为“使用预设”，已有配置或已修改草稿在替换前确认；取消保留原字段，确认后清空草稿密钥并要求重新填写，不能把原密钥沿用到新地址。自定义选择保留已有输入。发送同意弹层作为表单容器的同级节点，避免原生表单分支吞掉确认界面。

两名子 Agent 分别负责只读复审和定向回归。复审发现原生分支丢失发送确认、输入异步回声覆盖较新文字的风险，均已修复；字段只有预设明确重置时同步到原生状态。第一轮设备检查还发现长地址在行内裁切，改为独立可增高的字段后复测。

## 创建后固定接口格式与系统表单复核

用户明确接口格式应在创建时确定，并要求继续改善原生观感。本节取代前节“已保存服务可替换预设”的产品行为；前节仍是当轮验收记录。已保存服务不再出现预设或格式选择，草稿 setter 与编辑器固定原 provider；配置写入层拒绝更换已有 id 的 provider，且拒绝发生在密钥读取与写入之前。自定义新服务在创建页选择 OpenAI/Anthropic，其他字段保留。原“高级设置”改名“上下文窗口”，仅管理自动资料与手动值。

主表单将名称、地址、模型与密钥合为一组，移除纸色和卡片背景覆盖，采用 SwiftUI Form 默认分组、底色与语义文字颜色；不支持的联网能力不再显示无效行，支持时继续提供原服务级开关。上下文行显示“自动”或手动值；低频检查与删除保留。设计依据为 [Apple Settings](https://developer.apple.com/design/human-interface-guidelines/settings)、[Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields) 与 [Pop-up buttons](https://developer.apple.com/design/human-interface-guidelines/pop-up-buttons)，本轮原生系统样式不代表用户视觉验收完成。[新版编辑页](integration-service-form-fixed-type.jpg)。
