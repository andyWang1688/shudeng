# 阅读导航与标注回跳联测

任务：[GitHub #59](https://github.com/andyWang1688/shudeng/issues/59)。源码为 `codex/ui-product-integration`、HEAD `d663a77` 加工作区；本轮未提交、推送或正式发布。设备为 Shudeng Small，iPhone SE 第三代、iOS 26.5、375×667，只更新独立开发包 `dev.shudeng.integration`。

## 问题与修复

用户报告滚动模式从标注回到原文后卡住。设备上现有短样书和长章节在修复前未稳定复现同一次卡住；本轮定位到两个会造成类似现象的关联缺陷，不将其写成已证实的现场根因。

零尺寸定位目标会触发分页补救：给章节元素写入临时 minHeight，再用静态原文层恢复可见内容。旧实现也对滚动模式执行该分支，可能覆盖可滚动正文；从分页切回滚动又只改 flow，没有还原这些高度。修复将两处补救入口统一限制在分页模式，在实际执行 anchor 时再次核对模式；模式切换和销毁清理恢复层与自有高度，等待绘制的旧任务通过版本核对失效。高度按文档弱引用记录，保留作者原样式和后续外部修改。

## 自动化证据

`pnpm --filter @shudeng/reader-web test`：60/60 通过。新增 [7 项导航回归](../../../packages/reader-web/scripts/epub-scroll-navigation.test.mjs)执行真实 EpubReader 导航路径，DOM stand-in 提供零尺寸目标：分页恢复仍保留；滚动 goTo 与引用导航不覆盖真实目标、不写整章高度；切模式清理；等待期间切模式失效；原 minHeight 还原；后续外部改值保留。将同组测试中的 reader 源码替换为 HEAD 原实现后，1 项通过、6 项失败，失败表现为恢复层或 4000px 高度残留。受控测试证明该分支缺陷，不代替 WKWebView 现场复现。

移动端 55/55 定向检查通过，涉及 EPUB/PDF 高亮、标注路由、导航、偏好命令、退出、阅读设置保存与标注列表。reader-web、mobile 类型检查以及 `git diff --check` 通过。
