# EPUB 后台回收恢复

2026-11-24，用户报告书灯退到后台一段时间后返回，看到「阅读器已被系统回收，请重试打开书籍」。本轮在 Small（iOS 26.5）使用 Release 开发包复现 WebKit 内容进程终止并验证恢复。

## 回归

原实现的内容进程终止回调直接发出终态 `reader:error`，不重新加载，TypeScript 又保留已打开标记，因此用户只能看到错误页。新增回归先于修复运行失败：

- 原生 presentation 边界断言终止后应发出 `native:restarting`、重载同一 shell，并携带最近 CFI。
- React 边界断言重启后应重新发送 `reader:open`，且 ready 后重新同步标注。

修复后的原生 presentation 测试通过 17/17，阅读状态与命令相关测试通过 41/41。另覆盖后台不提前重载、回前台重载、WebKit 终止及导航取消不冒充新产品错误、旧异步任务隔离，以及恢复进程再次终止时停止自动循环并显示错误。

## 模拟器操作

1. 新 Release 包覆盖安装到 Small，打开《红楼梦》。
2. 用 Device Hub 回主屏，确认应用进入后台。
3. 终止该书灯实例对应的 `com.apple.WebKit.WebContent` 进程。
4. 等待 1 秒，确认应用没有在后台创建新的 WebKit 内容进程。
5. 执行 `xcrun simctl launch` 将书灯带回前台。
6. 出现新的 WebKit 内容进程，回到《红楼梦》同一原文位置和排版；页面没有「阅读器已被系统回收」或重试覆盖层。

## 验证范围

工作区类型检查通过，全量测试 1,159 项通过、9 项跳过、0 项失败；`bash scripts/build-ios-rn.sh Release` 构建成功。最终包再次执行上述主动终止流程，回到《红楼梦》同一原文位置，没有错误或重试覆盖层。

本次以主动终止模拟器 WebKit 进程触发同一 native 回调，验证了用户报告的故障路径。真机长时间后台、iOS 实际内存压力下的回收时机、应用本身被系统强杀后的恢复仍需真机另行验收。
