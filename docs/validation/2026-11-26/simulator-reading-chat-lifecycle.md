# 模拟器阅读恢复与问答往返

Shudeng Small（iOS 26.5），本地 RN Release 包。阅读和问答使用模拟器已有的《红楼梦》EPUB 与《段永平投资问答录》PDF，以下场景由本机 Chat Completions 流式服务提供受控响应。关联 [#61](https://github.com/andyWang1688/shudeng/issues/61)。

| 场景 | 操作与结果 |
| --- | --- |
| 阅读时 WebKit 被回收 | 从含书签、高亮和标注的正文切到 iOS「设置」，终止确认属于书灯的 WebKit 进程。切回后书灯进程未重启，新的 WebKit 进程恢复原页，排版和标注与离开前一致。 |
| 书内问答引用卡住 | 从阅读页提问，点回答下的原文引用。修复前问答已退出，阅读工具仍处于等待状态，「返回问答」无效。冷启动后再次复现。Expo Router 可丢弃已移出栈的页面发来的退场通知，原实现一直依赖该通知。 |
| 修复后引用往返 | 等导航栈确认原阅读页重新成为当前页，再定位引用。半屏和全屏分别点引用、查看高亮原文、点「返回问答」，同一轮回答和弹层高度恢复，阅读器回到提问前的 EPUB 位置。也从「对话」重开该会话并实测引用往返。连续操作没有发出额外模型请求。 |
| 回答在后台结束 | 等受控流式请求开始后切到 iOS「设置」。修复后重新覆盖安装的包上，SQLite 状态从 `streaming` 变成 `done`，终态已保存时「设置」仍在前台。切回书灯可见完整回答，服务端只收到一次请求。 |
| 后台时间用尽 | 让测试服务每 1.45 秒发送一个字符。切到 iOS「设置」时数据库已保存 20 字，后台继续收到 30 字。系统给书灯的后台时间到期后，服务连接关闭，数据库标记本轮未完成。回到书灯看到保留的正文、到期提示和重试按钮。点一次重试后回答完成，服务只收到一次新请求。 |
| PDF 引用往返 | 在第 60 页提问，点引用到第 41 页，再点底部「问问这本书」回到同一轮。数据库里的引用页和当前页都为 41。 |
| 从历史查看 PDF 引用并继续阅读 | 在更新联网设置后的 Release 包上冷启动，从「对话」打开同一段 PDF 对话，展开全屏并滚到第二轮。点「第 41 页」可读到原页；点左上「返回问答」仍是原全屏会话，第二轮的出处仍在视野中。关闭回到筛选后的对话列表，再从书架重开 PDF，正文与刚才的引用页一致。SQLite 核对为提问第 60 页、引用第 41 页、续读第 41 页，用户消息仍为 4 条。PDF 保留引用页是既有行为。 |
| 手动停止并重试 | 慢速回答收到部分正文后主动停止。数据库保存为 `cancelled`，正文 21 字，收起重开仍可见。重试完成 30 字，只发送一次新的模型请求，问题仍只有一条。 |
| 服务端提前断流并重试 | 服务端发送部分正文后直接断开。旧版把 21 字标为 `done`。修复版保存为 `error`，页面保留 21 字并显示「AI 服务的回答在传输途中中断，请重试」。点「重试回答」后保存为 `done`，正文 30 字，只发送一次新的模型请求，问题仍只有一条。 |

回归测试模拟退场事件缺失，两种 Expo Router 路由栈形态均通过，旧代码对同一测试均失败。断流回归覆盖 Chat Completions、DeepSeek、OpenAI Responses、Anthropic，以及断流时阻止执行未完成的工具调用。全工作区通过类型检查、1,172 项自动化测试（9 项跳过）、Release 构建和模拟器覆盖安装。

## 发送后立即停止

受控回归分别卡住首条消息保存和模型准备。旧代码在停止后仍尝试启动已取消的请求，或继续等模型准备返回。修复后，问题保存完即标为已停止，未开始的模型不会启动；若还在准备，直接结束本轮等待。模型准备中的本地读取或共享索引允许自行完成，不能继续启动这一轮。已有回答部分与后台时间用尽的状态仍按原规则保存。
