# 阅读 Agent 与 RAG 开发契约

本文是当前 Agent、检索、来源与上下文管理的开发正文。业务范围见[产品规范](../product-scope.md)，架构取舍见 [ADR-0019](../adr/0019-react-native-langchain-architecture.md)，实际通过/失败/未验证项见[验收索引](../validation/README.md)。

## 系统边界

Agent 运行在设备内，由宿主绑定当前书；用户配置的模型服务处理推理，书灯提供本机查书工具。范围是当前整本书，不跨书架。提问选文明确问题指向，不能替代书籍范围或来源位置。

LangChain/LangGraph 承担工具循环与状态编排，Deep Agents middleware 承担指导文件加载；书灯维护原文、索引、定位、预算和引用。开发先读项目技能 [ecosystem-primer](../../.agents/skills/ecosystem-primer/SKILL.md)，再从[技能索引](../../.agents/skills/README.md)选择当前任务所需技能。通用示例不授权增加服务器、云向量库或执行工具。

## 导入、切分与索引

导入或准备时按阅读顺序提取原文与稳定位置，切分、计算本地向量，并保存关键词与向量共同指向的来源身份。提问时只为查询生成向量，不为每次提问重新向量化整本书；内容或提取、切分、embedding 方案变化时判断兼容性，重建或版本化索引。

EPUB 保留章节/spine、资源 href、段落顺序和精确 offset，资源读取按 [EPUB 合同](epub-resources.md)。PDF 保留页码和页内位置；双栏、页眉页脚、跨页句与文字顺序需真实文件验证。清理检索文本时保留原文映射，不能让去空白破坏引用；扫描页不伪造文字，也不自动加入 OCR。

切分先尊重章节、段落、句子，再服从实际 embedding tokenizer 的输入上限；超长句也要有界处理。当前本地实现采用 ONNX、SQLite FTS5/BM25、向量余弦与融合排序，主要入口为 [chunker](../../packages/core/src/rag/chunker.ts)、[retriever](../../packages/core/src/rag/retriever.ts)和 [search-index](../../packages/core/src/rag/search-index.ts)。块长度、重叠与排序参数以源码和题集证据为准，不把框架默认值视为最佳参数。

模型必须准备好才能以实际 tokenizer 上限约束切片；不兼容或过长输入真实报错。无重叠切片依靠原文读取补邻文；查询切分、中文术语候选和合并均保留预算。相同维数不证明模型兼容，索引未准备好不能伪装成“没有相关内容”。

## 来源身份与引用生命周期

| 标识/数据 | 用途与生命周期 | 不能替代什么 |
| --- | --- | --- |
| 书籍身份与内容/索引版本 | 区分当前书及其可读取的一版资料。 | 同名书、同维度向量不代表同一内容。 |
| chunkId、sourceVersion、locator | 标识实际片段和原文位置；相同文字在不同位置仍是不同来源。 | 不靠文字去重丢掉位置，不拿显示页号当稳定来源。 |
| chunk readRef、nextCursor | 片段读取引用和续读游标包含相应身份/版本约束，原样传回工具，宿主仍限制当前书。 | 不是轮内引用编号，不由模型自行拼装或跨版本复用。 |
| 目录 reference | 在当前书、当前索引下解释的章节引用；当前实现可为 chapter:N，重建后重新取目录。 | 其字符串本身不保证携带书籍或版本，也不能独立检测所有跨版本复用。 |
| EvidenceRegistry 的 E1、E2… | 本轮实际取材的证据编号，供回答引用核对。 | 不是跨轮稳定的书内主键，不能只存 E1 就丢掉原文和定位。 |

端口以 [BookExcerpt/BookPassage](../../packages/core/src/agent/book-source.ts)为准，索引适配见 [SqliteBookSource](../../packages/core/src/rag/book-source.ts)，证据登记与核对见 [evidence.ts](../../packages/core/src/agent/evidence.ts)。BookExcerpt.quote 是来源原文真值，展示 context 可能更短；这不代表整段 quote 已送入模型。保存后的来源必须保留核对所需的原文、位置与关联，重新打开不能仅依赖已经消失的内存 registry。

## 单轮流程与工具

每轮固定当前书、问题、选文与位置、必要历史、模型/联网/指令配置快照；之后的设置修改下一轮生效。选文含“他”“这句话”等指代时，读取有界邻文帮助解释；定位不精确时说明范围，不能凭重复文字任意选一个位置。

Agent 根据指导与实际结果调用工具，可换搜索词、多次补读或扩大章节覆盖；RAG 检索嵌在查书工具中，不强制额外运行一轮固定预检。工具次数、时间、输出容量、循环与取消由执行层限制，Skills 不能解除这些限制。

| 工具 | 输入 | 结果合同 |
| --- | --- | --- |
| search_book | 自然语言或关键词 query，及实际 schema 支持的可选范围/容量。 | 当前书内有界原文、章节或页码、引用编号、readRef 和可用性/截断信息；不返回向量数组。 |
| read_book_passage | 选文定位、搜索 readRef 或目录 reference，可选邻文范围与续读游标。 | 连续原文、真实覆盖位置、精确度/说明、截断与 nextCursor；不能将截断材料说成已读完章节。 |
| get_book_outline | 有界目录请求，可带实际支持的游标。 | 章节身份、标题及可读 reference；目录多时可继续读取，具体层级字段以端口为准。 |
| read_page / read_chapter | 原有页码或章节引用。 | 兼容已有调用入口，沿用同一当前书、容量与权限边界。 |

具体 schema 与文本格式以 [tools.ts](../../packages/core/src/agent/tools.ts)为准，端口字段以源码为准；不要在文档维护另一套 JSON 协议。关键词与向量在 search_book 内部融合，Agent 无需分别调用两种搜索工具；关键词偏向名称、术语、原句，向量补充语义候选，两者的相关性分数都不等于事实置信度。

例如对“作者为什么这样说”，先结合选文把查询写成“群体压力如何影响独立判断”，搜索取得 E1 与其 readRef，再按 readRef 读上下文；材料不够时换查询或补章节。E1 只在本轮解释引用，readRef 用于工具继续取材，原文位置用于最终回跳。这是语义示例，不是承诺固定调用次数或固定返回字段。

空结果、资料不可用、截断、近似定位与执行失败必须区分。达到预算时保留已取得的材料，回答如有结论应说明依据和覆盖限制；不能声称搜索成功、读完全书或工具已执行。整书总结使用目录规划章节覆盖，受限部分明确标明。

## 上下文与资源预算

上下文管理入口为 [context-manager.ts](../../packages/core/src/agent/context-manager.ts)与 [request-context.ts](../../packages/core/src/agent/request-context.ts)。预算包含系统规则、历史、工具调用及结果，并为输出预留空间；界面显示的是估计用量，不把它当服务端精确计费值。

当前策略先裁剪过长工具结果，再摘要较早历史，必要时按完整消息组裁除。工具调用与对应返回保持成组，避免留下无法配对的消息。摘要明确标为“此前对话摘要，仅作背景，不是书内原文”，不能当新书内依据；摘要失败沿用保留近期安全消息组的回退，而非编造摘要成功。

引用需要保护的不变量是：仅以本轮模型请求实际发送过的原文作为取材依据，裁剪后从未发送的部分不能伪装为已读；需要时通过工具重新取回。该要求与当前核验实现的区别见下文。压缩后仍超预算时按 ContextBudgetError 真实终止并提示新建对话或缩短问题，不静默越窗发送。具体 token、字数和阈值由源码维护；上下文压缩不改写原始历史记录，也不等于后台执行恢复。

## 联网与配置

联网采用服务商内置搜索，由模型服务执行，沿用其服务地址、密钥及模型配置；不增加独立搜索 API/MCP。OpenAI 与 Anthropic 分别适配，自定义/中转地址缺少显式能力确认时只做书内问答，模型名称或“OpenAI 兼容”不足以证明搜索可用。

联网开关在各服务编辑页独立保存，默认关闭。旧全局偏好仅一次迁给当时选中的服务，已有服务级值优先；其他服务及新增服务不继承。当前轮使用配置快照，切换服务不能污染其他服务偏好，迁移与保存失败需真实处理。

只有明确的搜索能力错误且尚未输出正文时，允许本轮移除联网工具后重试一次。鉴权、额度或一般参数错误保留原错，已有正文后不重复发起整轮请求。网页标题/链接来自实际服务商元数据，不伪造看不到的网页正文或搜索过程。复用密钥不表示搜索免费，费用在服务配置说明中涵盖。

助手自定义指令统一作用于各书，控制人设、语气、语言、详略和协作偏好；保存后下一轮生效，当前运行不追溯修改。偏好保存失败保留编辑内容，损坏配置明确报错。外部 MCP 是独立扩展，保留已有配置、白名单、密钥及首次调用确认，不能因为内置搜索而直接删除。

服务端点与密钥装配见 [aiConfig](../../apps/mobile/src/platform/aiConfig.ts)，当前书与执行接线见 [bookChat](../../apps/mobile/src/platform/ai/bookChat.ts)。模型服务发送说明仍遵守 [ADR-0012](../adr/0012-confirm-ai-send-scope-on-setup.md)。

## 指导文件、权限与引用

产品 Agent 的基础规则、用户指令与阅读 Skills 在 [reading-guidance.ts](../../packages/core/src/agent/reading-guidance.ts)等运行时代码装配；通过 Deep Agents 的 memory/skills/filesystem middleware 读取虚拟 StateBackend。仅开放读取指导文件，不挂载设备文件系统，不开放执行、写入或产品子 Agent；框架文件存在不表示已加载。

阅读 Skills 指导选文解释、书内查证和整书总结的方法；书籍文本、用户人设与 Skills 都不能开启关闭的联网、改变当前书权限、伪造出处或解除预算。产品运行时指导与仓库 AGENTS.md、.agents/skills 的开发技能分开。

书内工具登记渲染的来源，回答用轮内证据编号引用；核对编号、连续原文与位置关系后保存，未知、重复或伪造引用按核对规则剔除并保留警告。网页来源另存实际元数据。重要书内结论应有依据，无依据时明确说明；出处匹配证明内容存在，回答推断与总体质量仍需单独验收。

核验要区分三层材料：源片段全文、工具实际渲染原文、每次请求经过预算/压缩后实际发送的原文。现有 EvidenceRegistry 与 rendered 映射、请求发送材料账本不是同一个对象；上下文裁剪更新 rendered 映射，最终引用核验仍以 registry 为依据，入口见 [agent.ts](../../packages/core/src/agent/agent.ts)。因此本轮只读核查不能证明裁剪后的严格引用边界已经满足，需专项验证“引用从未发送的尾部原文应被拒绝”等场景；不能把登记成功直接描述为发送范围核验通过。

## 前端、持久化与中断

assistant-ui React Native 的 useExternalStoreRuntime 适配 AgentEvent 和已保存消息；Gorhom Bottom Sheet 处理两档吸附、连续外观、滚动和键盘协作。宿主保护当前书、会话、聊天输入与生成状态，业务插槽承载选文/引用/上下文；组件来源与本地差异见[模块说明](../../apps/mobile/components/assistant-ui/README.md)。

切换高度不重建会话，关闭不停止生成，明确停止才取消执行；系统中断保留已收到并保存的内容并显示未完成。消息、引用、工具状态与 checkpoint 的保存遵循现有事务与序列边界；重开 UI 不等于再次发送，重试也不等于从任意 checkpoint 接续执行。未实现的恢复能力不能靠 UI 文案承诺。

## 场景验收

| 输入与操作 | 预期结果 | 禁止结果 |
| --- | --- | --- |
| 选中含指代、书中多次重复的句子提问 | 基于准确选文位置读取邻文；位置不精确时明确说明。 | 靠相同文字跳到另一章并声称精确。 |
| 用原词、同义词和自然语言询问同一主题 | 查当前书，两路候选按来源融合，必要时换查询补读。 | 跨书检索、把相关性当事实概率，或把不可用说成零命中。 |
| 要求整书总结，目录/材料超容量 | 分批取目录与正文，记录真实覆盖和未覆盖部分。 | 只靠少量命中声称读完每章。 |
| 工具返回截断/nextCursor 或上下文触顶 | 原样续读或明确限制；摘要不当证据，超窗真实失败。 | 拼造游标、引用未送入的材料、静默越预算。 |
| 联网关闭、能力不支持、鉴权失败或已出正文 | 分别验证关闭、能力单次回退、真实鉴权错误及不重发正文。 | 无授权搜索、把所有错误吞成降级成功。 |
| 生成时展开/关闭/重开，或明确停止/系统中断 | 会话、输入与状态正确保留；停止与中断真实呈现。 | 重发、丢草稿、关闭即取消、残缺回答标完成。 |
| 保存来源后重开，再点击书内/网页来源 | 保留各自真实来源并按类型跳转；原文不可用时说明。 | 只存 E1、编造网页、同名书误回跳。 |

按改动选择相关场景，协议单测、真实服务商质量、SQLite 持久化和设备交互分别留证据。原讨论、备选与虚构 JSON 示例见[历史规格](../archive/planning/reading-agent-rebuild.md)；持续有效的合同以本页为准。
