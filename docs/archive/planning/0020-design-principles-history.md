# 以 Apple 设计理念为依据，建立跨端设计规范

## 背景

用户指出当前视觉 Demo 文案冗余、缺少明确设计取舍，要求完整阅读 Apple 设计原则后再归纳为项目规范。随后明确书灯未来面向多端，不能将设计原则限定为 iOS，也不能把 iOS 的控件与尺寸直接规定给其他平台。

原界面规范仍包含强制品牌行、口号、继续阅读卡片、自定义导航、固定色字尺寸和仅允许 UIKit 等约束，已与用户后续选择及 [RN 架构决策](../../adr/0019-react-native-langchain-architecture.md)冲突。仅在文件末尾追加新规则会保留多个相互矛盾的执行入口。

## 决定

1. 重写 [界面设计规范](../../design/ui-development-standard.md)，作为跨端设计、组件实现与视觉评审的单一入口。Apple HIG 是主要依据，跨端采用范围由书灯明确选择。
2. 产品语义、操作后果、内容层级与视觉角色跨端一致；导航、窗口、控件、输入、辅助技术与具体尺寸按目标平台适配。Android、Web 及其他桌面端另读本平台官方规范。
3. 保留阅读优先、渐进披露、上下文恢复和成熟组件优先的方向；替代旧规范的固定视觉与 UIKit 绑定，不把 HIG 解释为换框架、新增功能或复制 Apple 外观的指令。
4. 功能冻结期间先通过独立、示例数据的 Demo 快速确认目标端设计，再接真实业务。采纳原则不等于任何 Demo 已定稿，也不等于产品已通过视觉、可访问性或多端验收。

## 取代范围与保留事项

| 原约束 | 本次处理 |
| --- | --- |
| 强制品牌行、口号、继续阅读卡片与问答品牌标题 | 取消这些固定视觉要求；按当前用户决定与任务层级设计。继续阅读卡片的取消已由 ADR-0019 记录。 |
| 强制自定义导航、底栏，禁止系统大标题或特定栏形态 | 按端选择成熟导航与容器；保留四个主要目的地和既定业务语义，具体视觉另做基准。 |
| 全端固定色值、字体、pt 尺寸、SF Symbols，禁止系统语义色 | 改为共享语义角色与平台映射；平台资源、尺寸、单位和许可分别核对。 |
| 只允许 UIKit、禁止 WebView/其他界面框架 | 由 ADR-0019 管理技术路线；ADR-0014 的具体 UIKit API 保留为旧实现记录，组件优先的设计意图继续有效。 |
| 既有阅读、问答、存储与授权行为 | 本决策不改变。ADR-0012 的服务配置时发送说明、ADR-0013 的固定正文与覆盖控件，以及 ADR-0019 的问答弹层、全屏专注与生成生命周期继续有效。 |

历史设计稿、ADR 正文与发布验收保留用于追溯，不再作为冲突视觉条目的执行依据。旧规范正文可通过 Git 历史查看，不再另存一份并行有效的规范。

## 依据与验证边界

本轮由主代理与五个阅读代理分组通读官方 HIG 快照的 **158 篇主题正文及 15 个目录页**，包含文字、各平台章节、表格和图注；逐篇来源、适用性、来源差异与读取边界见 [完整阅读记录](../research/2026-11-06/apple-hig-reading.md)。未将视频、全部 SDK、原始媒体视觉检查或安装技能的转述冒充本轮通读范围。

本轮只更新研究与开发规范，未修改应用 UI 或业务，未进行构建、模拟器或辅助技术验收。未来端的实现与发布仍需独立计划和实际证据。
