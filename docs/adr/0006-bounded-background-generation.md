# 首发收窄后台生成范围

用户在验证后明确选择：首发支持几十秒内回答的后台完成，以20～60秒为验证目标；成功保存答案，系统中断时保留已经收到并保存的内容，回来提示重试，不把未完成回答标为成功。暂不引入协调服务器、任务编号和复杂后台恢复机制，以降低尚未上线产品的实现成本，把投入集中在阅读、问答和可靠保存。

此决定替代此前要求完整长任务后台路线的规划约束，但不取消本机可靠保存；关闭问答面板不取消生成。20～60秒不是系统保证的运行时长，也不是要求到60秒主动终止；重试不是接续原任务，不承诺强杀、断网后仍完成。已有模拟器短请求验证支持该方向，长请求失败证据保留供以后评估，见[后台验证](../../.scratch/first-release-decisions/issues/11-background-validation.md)。
