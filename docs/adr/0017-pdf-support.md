# PDF 支持范围与导入提示

## 背景

书灯此前只支持可重排 EPUB。用户要求完整支持 PDF。PDF 不是一种单一格式：

- **文字型 PDF** 的页面文字可被选中，可做文字高亮、搜索与 AI 问答；
- **扫描型 PDF** 的页面是图片，无法选中文字；部分扫描件带 OCR 隐藏文字，但可能有错字；
- 同一份 PDF 可以混合文字页与扫描页。

## 决定

- **一次发版包含完整 PDF 支持**：文字型 PDF 提供阅读、缩放、目录、页码/进度、书签、文字高亮/笔记、搜索与 AI 问答；扫描型 PDF 提供阅读、缩放与书签。**不做 OCR**（保持轻量），不承诺扫描件的文字高亮/问答。
- **不向用户展示“支持等级”或分类标签**；书架不区分 PDF/EPUB 的“能力等级”。
- **导入时完整检查每页文字是否可用**（用户可等待几秒），检查结果准确后再入库。
- **没有问题的 PDF 不显示任何提示**；有扫描页才显示纸白卡片，说明现状与仍可做的操作，按钮为「取消 / 继续导入」。
- 导入后，问题 PDF 在阅读器右上角显示一个「?」，点开显示同一段说明；**不在首次打开时自动弹提示**，也不在用户尝试选字时弹提示。
- 所有用户可见文案避免技术词，不出现“文字层 / OCR / 格式限制 / 这不是书灯的问题”等表述，只说明“现在能做什么、不能做什么”。

## 技术方向

- PDF 阅读使用系统 **PDFKit**（与 Apple Books 同路线），以保证文字选择、PDF 注解层与页级定位；EPUB 继续使用 Readium。
- 导入解析与文本抽取使用 PDFKit / Readium 的 PDF 解析能力；文字型 PDF 按页建立索引，AI 引用定位到「第 X 页 + 原文」。
- 扫描型 PDF 不进入文字索引；不提供 OCR。
- 不引入新的第三方依赖。

## 备选与取舍

- **Readium PDFNavigatorViewController**：可直接渲染，但不是 `DecorableNavigator`，无法满足“文字型 PDF 的高亮/笔记”要求；仅适合只读，故不作为完整方案。
- **微信读书式只读**：实现最省，但与用户“完整支持”的目标不符。
- **掌阅式 PDF 重排**：体验接近 EPUB，但重排/版面分析成本高、表格与多栏质量不可控，且与“轻量”定位冲突。
- **支持等级标签**：会让用户觉得 PDF 是二等公民；改为问题卡片 + 可随时查看的「?」。

## 后果

- 扫描件的选字提问、文字高亮、搜索与 AI 问答不可用；用户会看到明确且不带技术词的说明。
- PDF 与 EPUB 共享书架、标签、阅读进度和 AI 入口，但阅读设置不同：PDF 不提供字号/行距/滚动模式。
- 表格只承诺页级文本引用，不承诺还原行列结构。

## 实现备注（2026-10-29）

- PDF 阅读使用系统 `PDFKit.PDFView`（与 Apple Books 同路线），EPUB 继续 Readium；新文件 `PDFReaderController.swift` 不改造 3191 行的 EPUB 阅读器。
- PDF 导入检查、页级文本索引、封面生成都在独立串行 `DispatchQueue` 上使用 PDFKit，逐页 `autoreleasepool`，进度按 1% 回主线程；渲染仍在主线程。
- 文字型 PDF 的标注以 `PDFAnnotation`（highlight / underline + text 图标）渲染，`BookNote.pdf` 保存页号与归一化矩形，旧数据无该字段时不渲染。
- 点高亮弹 4 色调色盘；点笔记直接打开现有笔记编辑器（无独立 PDF 笔记菜单），笔记颜色创建后不在阅读器内修改。
- PDF 搜索与 AI 引用均为页级 locator（`pdf://page/N`），AI 引用显示「第 X 页 + 原文摘录」；`QuestionEvidence` 增加 `pdfPage/locationTitle`，EPUB 路径不变。
- 页文字检测：文字页以 `page.string` 判定；无文字页在文字页存在时抽样（最多 40 页，优先最后 10 页）做墨迹判断以识别纯白页；整本扫描 PDF 跳过逐页墨迹判断以保证性能。因此「整本扫描 + 空白尾页」可能把空白页计为扫描页，提示仍为“扫描版”。
- 导入期间禁用底部 tab；确认卡从 window 顶层 present，continuation 有取消/失败兜底，避免卡住导入状态。
- 不做 OCR、PDF 重排或表格结构还原。扫描版仅阅读、缩放、书签；文字型 PDF 支持阅读、书签、文字高亮/笔记、搜索与 AI 问答。
