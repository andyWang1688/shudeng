# 离线语义资料按需下载与大 PDF 单页默认

## 背景

v0.4.1 的 Release 包约 133MB：其中本地语义模型 82MB、二进制 53MB。514 页 PDF 在连续模式下稳态内存约 550MB、CPU 峰值 300% 以上；轻量级阅读应用不能把这两个成本隐藏起来。

## 决定

- **Release 不内置离线语义资料**。AI 设置提供「离线语义资料」下载/取消/重试/删除；资料从固定 GitHub release `semantic-model-v2` 下载（约 81MB），写入 `Application Support/Shudeng/SemanticModel`，逐文件 SHA256 校验后原子安装。
- 没有下载时，阅读、原文搜索、笔记、书签、PDF 阅读全部可用；书内 AI 语义检索不可用，界面明确引导到「我的 → AI 服务」下载。下载完成后自动重试已有书的语义准备。
- Debug/测试构建仍内置模型，保持离线测试能力；Release 通过构建脚本移除 `SemanticModel` 资源。
- **200 页及以上的 PDF 默认单页（pageViewController）打开**；小 PDF 保持连续滚动；用户仍可在页脚切换「单页/连续」。本轮不持久化模式选择。
- Release 打开 strip、关闭 testability；PDF 封面使用磁盘缓存；PDF 文档异步打开并在关闭时彻底释放视图/文档；启动不再重复准备已完成索引。

## 后果

- Release app 从 133MB 降到约 32MB（不含需下载的语义资料），二进制从 53MB 降到 31MB；首次使用 AI 需要联网下载约 81MB，之后本地推理与原来一致。
- 514 页 PDF 默认单页的平均内存/CPU 明显低于连续模式；用户主动切回连续时仍可能达到 ~550MB。
- 语义资料磁盘占用包含下载包与解压缓存（约 200MB），后续可优化清理/压缩策略。
- 未下载/下载失败的语义检索降级必须保持可见但不打扰阅读；错误分类与重试是 AI 设置的一部分。

## 备选

- 保留内置模型换取开箱即用：包体无法达到轻量目标。
- 去掉语义模型改纯关键词检索：包体最小，但抽象问题的召回下降，作为后续可选模式评估。
- 所有 PDF 强制单页：内存最好，但小 PDF 和习惯连续滚动的用户会不适应。
