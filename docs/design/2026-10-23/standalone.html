# 书灯：第一版视觉与交互设计

日期：2026-10-23。状态：用户已确认，作为原生实现的视觉、交互与验收基准。设计稿确认不等于原生视觉验收通过。

实现规则见[书灯 UIKit 界面开发规范](../ui-development-standard.md)，决策见 [ADR 0009](../../adr/0009-native-ui-design-baseline.md)，当前完成度见[原生视觉验收矩阵](visual-acceptance.md)。

返工执行规格：[GitHub Issue #23](https://github.com/andyWang1688/shudeng/issues/23)。

品牌文案：**一盏照书的灯，AI 照亮你读不懂的地方。**

## 产品与设计判断

核心价值是帮助读者在阅读遇到难点时，结合书中原文理解问题，再继续阅读。功能范围沿用 [产品范围](../../product-scope.md)；不增加通用聊天、推荐书城、阅读排行榜或学习任务。

用户已认可安静、有纸书温度的方向，并授权沿用原应用图标。设计保留四栏与阅读内问答：书籍和原文是视觉中心，控件按使用频率分层，灯光暖色只强调选文、提问和依据。用户已确认本稿的布局、组件与状态边界。

## 评审方式

优先打开本目录的 `standalone.html`：所有图片、图标、样式、交互页面及设计说明已内嵌，可单独复制后打开，无需启动服务。源文件修改后运行 `node docs/design/2026-10-23/export-preview.mjs` 重新导出；只保留一个不超过3 MiB的结果文件，失败时保留上一份结果并清理临时文件。

开发预览仍可用 Node.js 启动本目录的 `serve.mjs`，访问 http://127.0.0.1:8736 。旧预览服务退出会导致页面或后续资源无法加载；评审时使用上述单文件版本可避免此依赖。无外部字体、统计脚本、云服务和真实 AI 请求。

“设计总览”并列展示书架、选文、问答；“亲手体验”串起打开书、选择原文、提问、点击引用、回到阅读的流程。笔记、对话和我的可通过底部四栏或评审面板进入。支持浅色/深色、390×844 与 375×667 两种画布，以及六种正常/边界状态。

书籍、时间、阅读百分比、笔记、问答均为演示数据。追问、连接检查、导出和保存入口演示不代替真实功能；原模拟器的 v0.1.0、书库、密钥和记录不受影响。

## 页面设计

| 页面 | 主任务 | 视觉与操作规则 |
| --- | --- | --- |
| 书架 | 接着读，或选一本书 | 继续阅读放在书库之前；保留两列书架；优先显示 EPUB 原封面，缺失时用书名排版；搜索、导入、排序在各自位置 |
| 阅读 | 持续读下去 | 正文使用书籍排版，工具栏收敛为返回、目录、更多；保留明确的提问入口；选文后就地呈现高亮、笔记、提问 |
| 问答 | 理解当前疑问 | 沿用常见聊天结构：用户消息靠右、使用气泡，不额外显示“你”字；书灯回答靠左，使用灯泡标识与“书灯 · AI”身份文字；选文作为提问附件可展开；连续追问逐条排列；行内引用与来源卡均返回原文 |
| 笔记 | 回看原文与自己的想法 | 引用使用书籍字体与细色线；个人笔记使用系统字体；类型过滤和返回原文入口可见 |
| 对话 | 找回并继续读过的疑问 | 按书分组，以问题为标题，展示简短回答摘要与时间；无无书籍聊天入口 |
| 我的 | 管理服务与外观 | 原图标与原品牌文案；AI 服务显示当前配置；原文发送说明就近可见 |

## 视觉规范

| 类别 | 设计值 | 使用规则 |
| --- | --- | --- |
| 浅色 | 纸白 `#FCFBF8`；墨色 `#282B26`；辅助文字 `#64675F`；弱文字 `#696C63`；强调 `#8A590D` | 正文区保持均匀背景；暖色用于帮助与引用，书封保留各自色彩 |
| 深色 | 底色 `#20231F`；表面 `#292D27`；文字 `#F0F1E9`；辅助文字 `#C0C4B8`；强调 `#EDC579` | 保持同一层级，不以纯黑和高亮白制造强烈反差 |
| 字体 | 系统字体用于界面；宋体用于中文书页与引用，英文正文沿书籍排版 | 界面标题约31pt，页面分组18pt，正文15–17pt，书页默认20pt；原生实现支持 Dynamic Type，不锁死系统字号 |
| 间距 | 页面边距24pt；阅读边距约29pt；主要节奏8/12/16/24/32pt | 不用加大空卡片营造留白；以内容之间的距离分组 |
| 形状 | 容器16pt、输入12–16pt、书封3–7pt、圆形工具按钮 | 同类控件使用相同规则；书封与面板的形状来自用途 |
| 图标与触控 | 原应用图标1024×1024；小图标约20–24pt；主要触控区域44pt | 原生实现使用统一风格 SF Symbols；引用视觉标记较小，但触控区域扩展到44pt |
| 动效 | 面板进入约240ms；按压反馈；支持减少动态效果 | 只表达状态变化，不使用持续装饰动画 |

## 核心流程与边界

1. 从书架打开书籍，恢复阅读位置；在原生实现中复用已有阅读内核与保存逻辑。
2. 选中文字后就地提问。自由提问保留当前书范围和“仅已读”选择，范围限制继续由现有业务逻辑执行。
3. 问答显示选文和出处。引用与原文位置绑定，不把编号存在当作结论正确。
4. 点击引用临时查看对应原文，左上角明确显示“返回问答”；返回后恢复同一对话、追问、未发送草稿、选文附件展开状态和回答滚动位置。查看引用时不弹出选文操作菜单，避免遮住依据；编号引用与来源卡共享这条往返路径，Escape也可返回问答。

收起问答是暂时回到阅读，不是清空对话。再次点击“问问书灯”恢复原对话与草稿；普通阅读与普通选文不显示引用专用返回入口。本原型切换书籍或通过评审面板切换示例场景时重置演示会话；此行为不代替正式应用的数据保存规则。

## 交互闭环验收

| 操作 | 可见反馈 | 回到哪里 | 必须保留 |
| --- | --- | --- | --- |
| 点击行内引用或来源卡 | 原文高亮，显示“查看引用1”与“返回问答” | 同一回答的原滚动位置 | 当前书、追问、草稿、选文附件状态 |
| 点击“返回问答”或按Escape | 恢复问答面板 | 触发引用的位置 | 不重建空对话，不重复发送问题 |
| 收起问答，再点“问问书灯” | 面板重新打开 | 当前对话 | 消息、草稿、回答滚动位置 |
| 普通阅读与选文 | 普通工具栏或选文菜单 | 阅读/书架的正常路径 | 不残留引用专用返回点 |

验收不仅检查“能进入下一页”，也检查“如何回去、回去后保留什么”。浏览器回归入口：`ego-browser nodejs < docs/design/2026-10-23/tests/citation-roundtrip.mjs`。

空书架提供单一明确的导入入口；资料准备中允许先读书；回答生成中允许收起；网络失败保留问题与选文并允许重试；系统中断保留已有内容并明确标记未完成。

本原型用固定示例模拟这些状态。真实生成、保存失败、后台恢复、VoiceOver、系统大字号和原生性能的验收，属于后续原生实现阶段，本次不宣称通过。

对话身份不能只靠颜色区分：使用左右位置与提问气泡，AI侧保留明确角色文字；用户侧仅为屏幕阅读器保留“你的提问”标签，视觉上不显示多余的“你”。用户问题不再作为回答内容的大标题；附带选文和AI引用分别归属提问、回答，避免把原文误认为AI生成。生成中、连接失败和中断状态保留在书灯一侧。连续发送追问追加到当前对话，不覆盖上一轮；追问回复明确标记为设计演示，不伪装真实AI回答。
