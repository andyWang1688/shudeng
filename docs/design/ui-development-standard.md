# 书灯 UIKit 界面开发规范

状态：2026-10-23 用户确认，作为原生界面的规范性开发文档。本文里的“前端”指现有 iOS UIKit 展示层，不另建 Web 页面或第二套设计系统。

## 1. 文档优先级

发生冲突时按以下顺序处理：

1. [高保真原型](2026-10-23/standalone.html)决定视觉层级、布局、尺寸、颜色、组件形状和页面状态。
2. [设计规格](2026-10-23/spec.md)决定产品语义、交互闭环和验收边界。
3. 本文把两者翻译成 UIKit 实现规则；本文不得自行改变设计结构。
4. [视觉验收矩阵](2026-10-23/visual-acceptance.md)记录实际结果。功能测试通过不能代替视觉验收。

设计变更必须先更新原型与规格，再更新实现。代码现状不能反过来成为设计基准。决策背景见 [ADR 0009](../adr/0009-native-ui-design-baseline.md)。

## 2. 设计语言

书灯是安静的阅读工具，不是通用聊天工具或内容平台。

- 视觉中心依次是原文、书封、读者问题；AI 帮助只在需要时出现。
- 使用纸白、墨色和少量暖灯色建立层级，不用高饱和大色块、渐变或装饰动画。
- 用留白、字号和细分隔线组织内容。卡片只在“继续阅读”、输入区、问答依据等确有边界的内容上使用。
- 根页面保留书架、笔记、对话、我的四栏。页面标题左对齐并使用自定义页头，底栏保持平直。
- 阅读页使用书籍排版；界面控件使用系统字体，中文原文和引用使用宋体。
- 图标统一使用 SF Symbols 的 regular 线重；原灯泡图标只用于品牌标识、AppIcon 和必要的品牌识别位置。

## 3. 颜色令牌

Swift 令牌统一放在 `BookDesign`，业务页面不得写十六进制颜色或直接使用 `.systemBackground`、`.label` 等系统语义色替代本规范。浅、深色必须同时实现。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `paper` | `#FCFBF8` | `#20231F` | 页面底色 |
| `surface` | `#FFFFFF` | `#292D27` | 输入框、提问气泡等表面 |
| `wash` | `#F2F0E9` | `#31362E` | 继续阅读卡片、弱底色 |
| `line` | `#E6E3DA` | `#3D4338` | 分隔线、描边 |
| `ink` | `#282B26` | `#F0F1E9` | 主文字、主要图标 |
| `secondary` | `#64675F` | `#C0C4B8` | 辅助文字 |
| `muted` | `#696C63` | `#A8AD9F` | 弱提示、时间 |
| `accent` | `#8A590D` | `#EDC579` | 选文、提问、引用和选中状态 |
| `accentWash` | `#F5E9CC` | `#403725` | 引用编号、灯泡底色 |
| `selection` | `#F4E3AC` | `#5B4D2D` | 原文高亮 |
| `error` | `#A13C30` | `#F2AEA2` | 错误文字和图标 |
| `errorWash` | `#FAEBE7` | `#472E28` | 错误提示底色 |

暖灯色只强调阅读帮助，不用于整页背景、普通按钮的大面积填充或无关装饰。书封保留原封面颜色，不受界面色板限制。

## 4. 字体与字重

界面字体使用系统字体，书页和原文引用使用宋体。字号必须通过 `UIFontMetrics` 支持 Dynamic Type，并保持字号之间的层级，不得全局缩小系统字号来容纳布局。

| 角色 | 基准字号/行高 | 字重 | 规则 |
| --- | --- | --- | --- |
| 根页面标题 | 31 / 1.25 | 700 | 左对齐；不使用系统紧凑标题替代 |
| 品牌字标 | 21 / 1.25 | 650 | 与 25pt 灯泡标识间距 8 |
| 页面分组标题 | 18 / 1.3 | 650 | 例如“继续阅读” |
| 继续阅读书名 | 21 / 1.35 | 650 | 最多两行 |
| 页面正文 | 15 / 1.7 | 400 | 问答正文可用 15 / 1.85 |
| 辅助说明 | 12 / 1.6 | 400 | 作者、阅读位置、时间 |
| 弱提示 | 10–11 / 1.6 | 400 | 仅用于短信息 |
| 阅读正文 | 20 / 1.95 | 400 | 宋体，尊重阅读设置 |
| 原文引用 | 17 / 1.8 | 400 | 宋体 |

CSS 的 650/600 统一映射为 `UIFont.Weight.semibold`，550 映射为 `.medium`，700 映射为 `.bold`。不要用多个接近的系统字重制造无意义的层级差异。

## 5. 间距、尺寸和形状

全局间距节奏为 4、8、12、16、20、24、32pt。根页面左右边距 24pt，阅读正文左右边距约 29pt。组件内部尺寸按下表执行，不新增随手数值。

| 项目 | 规范 |
| --- | --- |
| 页面左右边距 | 24pt |
| 根页面底栏 | 81pt，包含底部安全区；纸白背景、1pt 顶部分隔线、四等分 |
| 底栏图标/文字 | 23pt / 10pt；选中时墨色，未选中辅助色 |
| 选中标记 | 顶部 19 × 3pt 暖灯色圆角条 |
| 搜索/输入框 | 最小高度 44pt，圆角 12pt，`wash` 背景 |
| 继续阅读卡片 | 圆角 16pt，内边距 17pt，封面 82 × 116pt，图文间距 17pt |
| 继续阅读圆形箭头 | 27pt 墨色圆，内部箭头 15pt |
| 书库封面 | 宽高比 2:2.8，左 3pt、右 7pt 圆角，不伪造出版社封面 |
| 问答面板 | 高度约为屏高 76%，顶部圆角 23pt，把手 33 × 4pt |
| 引用编号 | 视觉约 22 × 20pt，触控区域至少 44 × 44pt |
| 主要触控区域 | 不小于 44 × 44pt |

圆角只使用设计定义的 3/5/7/10/12/13/16/18/23pt 层级。圆角按钮必须保持圆形；卡片不使用胶囊形；底栏不使用悬浮胶囊。

## 6. 页面结构

### 书架

1. 首页顶部的品牌行包含 25pt 灯泡、21pt“书灯”和右侧 12pt 品牌短句。
2. 自定义页头为左侧 31pt“书架”和右侧 44pt 圆形导入按钮。
3. 搜索后显示继续阅读；继续阅读卡片必须同时包含封面、书名、作者、章节/百分比、进度线和“接着读”箭头。
4. 书库使用两列网格，卡片信息为封面、书名、作者、阅读状态；空结果显示明确导入入口。

### 笔记

页头、说明文案、四类过滤（全部、高亮、笔记、书签）和书籍分组均按原型。原文引用使用宋体与 2pt 暖灯色左边线；个人笔记使用系统字体。不得改成通用 `insetGrouped` 系统列表。

### 对话

页头与说明、搜索框、封面书籍分组、问题标题、两行回答摘要、时间和提问次数按原型排列。不得只保留系统导航标题和缩进列表。

### 我的

使用左侧 31pt 页面标题；下方是居中的 70pt 原图标、20pt“书灯”和分行品牌文案。AI 服务、外观、关于书灯使用 66pt 高的细分隔行，说明文字放在设置组之后。

### 阅读

顶部为自定义 51pt 工具栏：返回、书名/章节、目录和更多。正文默认 20pt 宋体、行高 1.95、左右约 29pt；底部中央是“问问书灯”胶囊按钮，不能改成横跨整栏的系统工具条。引用状态下左上角明确显示“返回问答”。

### 问答与引用

问答使用约 76% 高的底部面板，不得替换为普通全屏页面。顶部为把手、灯泡标识、“问问书灯”和关闭按钮。用户消息靠右显示气泡，选文附件位于气泡内；AI 回答靠左，显示“书灯 · AI”。输入区固定底部并使用自定义发送按钮。引用页必须保留清晰的返回入口、高亮原文和原对话状态。

## 7. 状态与反馈

- 加载：使用与最终布局同形的占位内容，不用页面中央的通用转圈。
- 空状态：按原型的标题、说明和单一主要操作呈现。
- 资料准备：显示可理解的进度与“可以先阅读”的限制，不阻塞阅读。
- 生成中：在书灯回答一侧显示状态，允许收起面板。
- 错误：在发生错误的内容附近显示原因和重试入口，保留问题与选文。
- 中断：保留已有回答并明确标为未完成，不伪装成成功。
- 按压：约 0.98 缩放和 0.72 透明度；面板进入约 240ms。开启“减少动态效果”时应移除位移和缩放。
- 保存失败：必须保留未保存内容，并提供明确退出或重试选择。

## 8. 代码组织与组件边界

- 现有展示层继续使用 UIKit；这些页面不引入 SwiftUI、WebView 或第二套主题框架。
- `UIViewController` 只负责页面组合、生命周期、导航和连接现有 Store/Service；View 组件只负责呈现数据和发出用户操作回调，不直接读取文件、Key、检索索引或 AI 服务。
- `BookDesign` 负责语义颜色、字体、显示工具和通用基础样式；共享品牌行、页头、底栏、书封、继续阅读卡片、分组标题、问答气泡、来源卡、输入区应从页面控制器提取为可复用组件。
- 页面私有组件可留在对应控制器附近；跨页面出现第二次时提取为共享组件。不要复制一套近似实现再分别微调。
- 尺寸先引用共享间距和组件常量；组件内部特有尺寸应集中为具名常量，不在约束中散落数字。
- 主题通过 trait collection 自适应，不在页面内维护第二份浅/深色布尔状态。用户外观选择仍由现有 `interface-style` 设置管理。
- 异步工作与真实 AI/保存状态继续使用现有服务和保存模型；返回 UI 的更新在主线程执行，不能在视觉返工中改变业务协议。
- 新行为应在现有 XCTest 接缝补回归；视觉结论必须另有同尺寸截图，不能把单元测试命名成“视觉通过”。

## 9. UIKit 实现规则

### 必须

- 根页面使用自定义页头、品牌行和平直底栏；不复用会改变外观的系统大标题导航栏或 iOS 26 悬浮 Tab Bar。
- 复用语义组件：品牌行、根页头、底栏、继续阅读卡片、书封、分段过滤、书籍分组、问答气泡、来源卡和输入区。
- 使用 Auto Layout 与安全区/键盘布局锚点；所有布局必须在 375 × 667 和 390 × 844 上成立。
- 所有颜色、字体、圆角、间距和图标尺寸从语义令牌或组件取得。
- 文本支持 Dynamic Type；辅助字号下允许增加行数和改变列数，但不得删除内容或打乱业务层级。
- 提供可访问标签、角色和顺序；装饰图从无障碍树隐藏；引用编号视觉可小，触控区域不可小。
- 保留现有保存模型、检索协议、AI 协议、Readium 阅读内核和可恢复状态。

### 禁止

- 用“系统原生感”为由替换设计中的导航、底栏、卡片或页面层级。
- 为消除布局问题而静默缩小字号、裁切文本、隐藏功能或改成紧凑标题。
- 在控制器中散落硬编码颜色、字体和间距；或为同一语义创建多个近似值。
- 只验证“能点、能跳、能保存”就宣告视觉完成。
- 读取或输出真实 Key、用真实 AI 请求代替固定验收，或把测试包截图当作正式设计证据。

## 10. 视觉验收门槛

一个页面只有同时满足以下条件才能标为通过：

1. 在 375 × 667 和 390 × 844 上，浅色与深色均完成同尺寸对照。
2. 页头、品牌区、内容顺序、组件形状、字体层级、边距、颜色和底栏与原型一致。
3. 正常、空、加载、错误或中断等相关状态均按规格实现。
4. 交互闭环可实际完成，并保留规格要求的数据与滚动状态。
5. 截图、测试记录和允许偏差均写入验收矩阵。

真实书名、作者、回答和时间导致的内容折行属于正常适配；需要改变组件、移动信息或削弱层级时，必须先记为允许适配偏差并获得确认。

## 11. 交付顺序

先完成“书架”两种尺寸、两种主题和空/准备状态，通过同尺寸对照后再依次完成笔记、对话、我的、阅读、问答和引用。每页通过后保留证据，不把未完成页面合并成一次“整体完成”的结论。
